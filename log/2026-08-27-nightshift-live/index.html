Nightshift live — 2026-08-27

Nightshift moved off its sandbox and now runs this project for real. Two things changed, and the docs written earlier the same day were already wrong.

What changed

  • INBOX.md is gone. chat.jsonl replaces it. The whole Telegram conversation, both directions, one {ts, from, text} per line, oldest first, append-only. Never edited, never deleted, nothing marked done. Read the tail, not the file. A matt line after the last agent line is unanswered — that single rule replaces clearing an inbox. harness lines do not count.
  • Speaking and logging are one action: ~/Documents/nightshift/bin/notify.sh. It sends to Matt and appends to chat.jsonl. Never hand-write the log.
  • No project .env, and there never will be. notify.sh reads the harness's own .env — one bot, one chat, shared. The earlier instruction that each project needs its own bot token was wrong and has been corrected upstream.

The trap, written down so future-me does not fall in it

The run stops when QUEUE.json is empty and the last speaker was the agent. Speaking closes the conversation. So every piece of unfinished work must be in QUEUE.json before sending anything. A "working on it" message with an empty queue ends the run.

What we did

  • CLAUDE.md line 14: INBOX.md → chat.jsonl. (Normally CLAUDE.md is left alone because editing it invalidates the cached prefix — Matt asked directly.)
  • docs/working-mode.md: the Telegram section was rewritten, not patched — it now covers chat.jsonl, notify.sh, the unanswered-line rule and the empty-queue trap. The Artifact exception survives unchanged.
  • docs/index.md was already correct — Matt had updated it.
  • .gitignore: dropped the .env line, which pointed at a file that will never exist. chat.jsonl stays ignored — it is a transcript, not knowledge, and the harness owns it.
  • INBOX.md was already deleted.
