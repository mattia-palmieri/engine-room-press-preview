Copy a real book site, don't invent one

What happened

Matt's line — "maybe we shouldnt reinvent the wheel, lets find a nice similar book website, check how they do on mobile and copy them" — sat unanswered for a round. The reply after it talked about the Surplus blurb instead. This session answered it.

What we decided

Measure, don't recall. A Sonnet subagent drove a real browser to Fitzcarraldo, Standard Ebooks, Persephone, Verso and NYRB Classics at 390px and 1440px and read computed CSS off the page. Numbers in docs/notes/book-site-teardown.md, screenshots in data/research/book-sites/.

They all do the same five things: 1. Two cover columns on a phone. Never one, never three. 2. The blurb is never in the grid — always one tap away. 3. Under the cover: title, maybe author, maybe price. Nothing else. 4. Tight gap (10–16px), small mobile side padding (15–24px). 5. Desktop capped around 1200–1450px.

Base pattern chosen: NYRB Classics — closest to us (type-only covers, true 2:3, no photography to crop) and the tightest mobile layout of the five.

Built as option D, "the bookshop", at /covers/options/layout-d.html: 2 cols ≤1000px, 4 above; 12px gap; 16px mobile padding; 1200px max; title only under the cover; blurb behind a CSS-only :target sheet (bottom sheet on phone, centred panel on desktop). No JavaScript. Verified in a browser: 165px covers at 390, 275px at 1440 (was 120px), no horizontal overflow, sheet opens and closes.

What we did not do

Did not touch the live /covers/ page. D is an option next to A/B/C; Matt still picks. Did not add filters or sort — none of the five reference sites uses that chrome below ~50 titles.
