Nightshift went silent 43 hours because a macOS permission dialog froze a round; fixed with a stall watchdog, a move out of ~/Documents, and a frozen Claude binary at a stable path.

The 43-hour freeze, and the three fixes

What happened

  • Round 1 started 2026-08-28 22:08 (Matt's "GitHub pages" message), made two tool calls, then froze until 2026-08-30 17:11 — 43 hours. Cost of the whole round: $1.00.
  • Matt sent three messages in that window. listen.sh logged them to chat.jsonl, but the frozen round still held the driver lock, so no new round could start. Total silence.
  • Cause: macOS put up a TCC dialog — "2.1.251" would like to access files in your Documents folder — and claude blocked on it. It unfroze when Matt dismissed it.
  • Why it appeared that evening: Claude Code auto-updated to 2.1.251. macOS keys permissions to the exact binary path, and every release writes a new ~/.local/share/claude/versions/<v> path. New path = permissions reset = fresh dialog.
  • Not quota, not tokens, not machine sleep (caffeinate held 55h, pmset shows no sleep).

The three fixes

  1. Stall watchdog (bin/nightshift.sh). Each round now runs in the background with a watcher on its .jsonl log. No growth for NIGHTSHIFT_STALL_SECS (default 900) → the round is killed, Matt gets a Telegram line, the loop starts a fresh round that answers the backlog. Smoke-tested: fires, kills, no orphans. Worst case is 15 minutes of silence, not 43 hours.
  2. Out of ~/Documents. Both folders now live at ~/work/nightshift and ~/work/history-books. Documents, Desktop and Downloads are the three folders macOS guards; work outside them does not trigger the dialog. The launchd plist, CLAUDE.md and docs/working-mode.md were repointed. (Frozen session notes and data/ still show the old paths — that is history, left alone.)
  3. Frozen binary. The harness runs /Users/matt/bin/claude-ns, its own copy at a path that never changes, set via NIGHTSHIFT_CLAUDE_BIN in the plist and CLAUDE_BIN in the driver. Auto-updates can no longer reset its permissions. bin/update-claude.sh moves it forward deliberately — run it only when Matt is at the Mac.

Matt allowed the Documents dialog once for claude-ns (Claude Code still peeks at ~/Documents at startup). That grant now sticks across updates.

Open questions

  • The harness binary is pinned at 2.1.251 and will drift from the installed one. Refresh it from time to time with bin/update-claude.sh, never mid-weekend.
  • Other permissions (Chrome automation, screen recording) can still ask on first use. Probed them while Matt was at the Mac to flush the dialogs early.

Pointers

  • ~/work/nightshift/bin/nightshift.sh — watchdog block sits around the claude -p call.
  • ~/work/nightshift/bin/update-claude.sh — deliberate binary update.
  • ~/work/nightshift/state/ctx-trace.log — per-tool timestamps; the 43-hour gap is visible.
  • Heredocs (<<'EOF') hang in the cmux interactive shell — write the script to a file first.
