Fixed the messy text-over-grid look — the grid now anchors to the text, not the viewport, and is vertical-lines-only on paper surfaces; every card, cover and page padding is a whole number of modules.

Design alignment — the grid fix

The diagnosis

Matt said the look was right but "text over background feels messy". It was not the type and it was not the spacing. Every surface drew its 40px grid from the element's own edge (0,0), while every content edge sat at a number that is not a multiple of the module:

surface grid module old content padding
Instagram card 40px 72px
news card 40px 72px
book cover 50px 108px
landing page 40px 24px, plus a centred column, so the offset changed with every screen width
cover shelf / ballot 40px 24px

So no text edge ever landed on a line, on any surface, at any size. The grid read as noise behind the type instead of the structure under it.

What we changed

Two rules, now written into design.md as rule 7.

  1. Paper surfaces get vertical lines only. Horizontal lines cross every line of type at a random height — that is the single biggest source of the mess, and no baseline grid fixes it without freezing all the leading. Removing them was cheaper and looks better. Vertical column lines behind left-ranged text read as drawing paper.
  2. The grid is anchored to the text column, never the viewport. On the landing page and the ballot the lines are drawn inside the content box of a fixed, centred layer of the same width and padding as the text column (background-origin/clip: content-box). The column's left edge is therefore a grid line at every screen width, with no media-query arithmetic.
  3. Flat-field surfaces keep the full grid, and the padding moved onto it. Card 80/80/70 on a 40px module (1350 − 80 − 70 = 1200 = 30 modules). Cover 100/100/110 on a 50px module (2560 − 100 − 110 = 2350 = 47 modules). The odd bottom value is deliberate: the canvas heights are not multiples of the module, so the bottom padding absorbs the remainder and both content edges land on a line.

Also on the module now: landing --pad 20/40, column 760/880, section padding 40/80, h1 margin 40/60; card callout 120/40; cover callout and title 50. Cover text column is now 1400px, so size_for() divides by 1400.

What we tried and rejected

  • A true baseline grid (every line of type on a 20px or 40px rhythm). Rejected: 19px Newsreader at a comfortable 1.6 leading is ~30px, which fits neither 20 nor 40. Forcing it means either cramped or airy body copy, and still fails the moment a heading wraps to a different number of lines.
  • Snapping every hairline to a grid line by hand. Rejected as fragile: a rule deep in the page inherits the cumulative height of every text block above it, so one edited sentence breaks it. Removing the horizontal lines removes the problem instead of policing it.
  • Keeping the viewport-anchored grid and just choosing nicer paddings. Cannot work: the column is centred, so the offset between grid and text changes with every browser width.

Second pass — what the audit caught

The first pass fixed only the padding box. A pixel audit (data/audits/grid-alignment-2026-08-31.md) found the left edges clean everywhere and four systemic vertical defects, all from elements placed by line-height or flex rather than by a module:

  1. Card and news-card callout tag floated at y=234–281 instead of 240–280.
  2. Cover callout tag floated, and moved between covers — it was positioned by flex leftover space, so a title with a leading "THE" pushed it somewhere else.
  3. Footer hairline floated on all seven card and cover files.
  4. Landing page on the phone: the first grid line was not drawn at the text column's edge. Cause was background-clip:content-box swallowing the line at the exact content edge; replaced with background-position-x:var(--pad).

Fixes: an explicit line-height of exactly one module on every rail, tag and footer; a fixed 750px spacer pinning the cover callout to y=900 on all sixteen; footer padding-top 39px/49px so the 1px border itself lands on 1200/2350 — 40 and 50 were one pixel out, which is the kind of thing only a pixel scan finds.

Re-verified by pixel scan on all 29 rendered files: card tags 240–280, cover tags 900–950, footer rules 1200 and 2350. Zero defects.

A side benefit worth keeping: pinning the cover callout means all sixteen covers now break at the same height, which makes the shelf read as one series.
