The whole preview site is now generated from docs/ by bin/build_site.py — one hub links every deliverable, decision, note, session log and the queue.

Site hub — one link, everything navigable

What Matt asked for

"I'm on Telegram, on a phone, can only read your messages or check html on github pages. Make sure you put everything on html, so that I can open one link, and from there see not just your lp and other content proposition, but that's also how you communicate what you've done, why, different ui propositions etc, all navigable from main page."

So the site is no longer a place to park two drafts. It is the report.

What we decided

  • Generate, never hand-write. bin/build_site.py builds data/site/ from docs/*.md, docs/notes/, docs/sessions/, DECISIONS.md, QUEUE.json and the built surfaces in data/. bin/publish.sh runs the build then pushes. Docs stay the single source of truth; the site can never drift from them.
  • The hub is five numbered sections, in Matt's order of interest: 01 the work you can look at · 02 what I decided and why · 03 the research under it · 04 what is next (the queue) · 05 what happened, night by night.
  • The hub uses the Technical Drawing system. The old index was parchment-ish — the exact register we banned. Gone.
  • A black "Back to everything" bar is injected into the copied surfaces (landing, cards, design directions) at build time. It breaks the "one action on the landing page" rule on purpose: on a phone, a dead end is worse.
  • python3 -m markdown is installed with --break-system-packages --user; build_site.py adds the user site-packages path itself, so it works headless.

Rejected

  • Hand-maintained HTML pages per doc — guaranteed to go stale within a round.
  • A static-site generator (Eleventy/Hugo) — needs node, config, themes. The whole build is 200 lines of Python and produces exactly the design system.
  • Exposing chat.jsonl on the site — Matt already has it in Telegram, and it is the one thing that should stay private.

Open

  • Phone-render audit was running when this note was written: data/audits/hub-phone-render.md. Fix anything it found, then republish.

Pointers

  • bin/build_site.py — the generator. bin/publish.sh — build + push.
  • docs/working-mode.md — new closing section: republish after every round that changes a doc or a deliverable.
