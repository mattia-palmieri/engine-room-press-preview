Access recipes, and what is still blocked

Amazon — WORKS, no warm-up needed (re-verified 2026-08-27)

Cold deep links work. Seven product/bestseller pages opened back to back with no homepage visit first, no bot wall, no captcha, no rate limit. The earlier "warm the session first" recipe is a fallback, not a requirement.

What actually matters is cookie freshness on disk, not per-session warm-up. The profile at ~/.agent-browser/profiles/real-browser already holds valid Amazon cookies, and they survive rb close, reopen and reboot.

rb open "https://www.amazon.com/dp/<ASIN>"
rb wait --load networkidle
rb get text body | grep -iE "best sellers rank|global ratings|out of 5 stars|\$[0-9]+\.[0-9]{2}"
rb key End        # only if BSR is missing — it is lazy-loaded, position varies

A wrong ASIN returns a real "Page Not Found" page — that is not a block. Do not read it as a bot wall and fall back to guessing. Retry with the right ASIN.

If you ever do hit a genuine wall (cookies wiped or expired), re-seed: open https://www.amazon.com, do one real click (search a title, click the result), then deep links work again.

Gotchas, all verified the hard way: - The URL slug is cosmetic; only the node id is real. /Best-Sellers-Books-World-History/zgbs/books/4999/ returns Iran History. Confirm against the page title, never the slug. Known: books/9 = History. - Rank is per edition, and the spread is enormous. Sapiens paperback was #62,645 in Books while the Audible edition was #515 in Audible. Never compare a BSR across formats, and always record which edition a rank came from. - BSR is a poor cross-title metric even within one shelf — Salt #873 vs Crashed #430,728. Goodreads rating counts are the steadier scale signal. - The bestsellers department sidebar is lazy-loaded — scroll and re-snapshot. - rb find role link click --name "Books" failed where rb click @eNNN from a fresh snapshot worked. On Amazon, prefer snapshot-then-click-by-ref.

The shared browser is a single resource — parallel subagents collide

Verified 2026-08-27, the hard way. rb is one shared Chrome daemon. When two research subagents run at once, they hijack each other's navigation — one agent was caught mid-task loading a page a different agent had requested.

Rules for any fan-out that touches the browser: - Always confirm the URL that actually loaded before trusting scraped text. Silent hijack looks exactly like real data. - If contention appears, clone the profile into an isolated session, work there, and delete the clone when finished. This is proven to work. - Prefer serialising browser work, or give only one subagent per round the browser.

Substack — paid tier prices are NOT publicly visible

Checked across 11 history publications on 2026-08-27. Every /subscribe page shows only a free email capture. The price picker appears only after entering an email and entering checkout, which we do not do. Any newsletter price norm (e.g. "$5/mo or $50/yr") is unevidenced — do not state one. Subscriber counts, however, ARE often displayed (15,000-203,000 observed) and make a better scale signal than price.
