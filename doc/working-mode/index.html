How the agent works while Matt is away and reachable only on Telegram.

Working mode (away period, from 2026-08-28)

Matt is away for ~3 days with a phone only. He can read Telegram. He cannot open a PC, a local file, or a terminal.

The single goal

The fastest first EUR 1 from a paying stranger. Not a salary model, not an audience, not a book. Every decision is judged against how much it shortens the path to one stranger paying.

Order of work — do not invert it

  1. Business — competitors alive and dead, real demand, how money is made.
  2. Distribution — evaluate every channel, then choose one.
  3. Brand, landing page, offer.
  4. The book, last. Whether we can write well is not the open question.

The rule about verdicts

Matt's standing instruction: assume a viable angle exists and find it. Concluding "not viable" almost always means we were too strict or did not consider enough options. If a path is blocked, name the next-nearest path.

Talking to Matt — Nightshift is live

Nightshift (~/work/nightshift) runs this project unattended. One bot, one chat, shared with the harness. This project has no .env and never will.

chat.jsonl (project root) is the whole Telegram conversation, both directions: one {ts, from, text} object per line, oldest first, append-only. from is matt, agent (you, in an earlier round) or harness (the driver). It is your memory of the conversation — Matt refers back to what he said and to what you told him. Nothing in it is ever edited, deleted, or marked done.

Read the tail, every round, before anything else:

tail -n 20 chat.jsonl | jq -r '"\(.from): \(.text)"'

A matt line after the last agent line is unanswered. Answer it and treat it as him speaking. harness lines do not count. That one rule is the whole protocol — there is no inbox to clear.

Speaking is one action, and the only way to speak:

~/work/nightshift/bin/notify.sh "your text"

It appends your line to chat.jsonl and sends it to Matt. Never write to chat.jsonl by hand.

The trap

The run stops when QUEUE.json is empty and the last speaker was you. So speaking closes the conversation. QUEUE.json is the only place unfinished work lives — put everything outstanding in it before you send anything. A "working on it" message with an empty queue ends the run.

When to speak

Adaptive, not scheduled. Speak when blocked with a real question, and when something big is unlocked or finished. Not for status noise.

Artifact exception

The global rule says never use the Artifact tool for wireframes and mockups. That rule is suspended here: on a phone, an Artifact link is the only way Matt can see a page, a table, or a long document. Publish deliverables as Artifacts and send the link. Still write the local file in data/ too, for when he is back at a PC.

Delegating research — the rules that came from a failure

The first market-living run was marked done on a file where 84 numbers were model-memory guesses labelled "(unverified)". It cost a full re-run to fix. The cause was not a blocked source — it was a budget squeeze plus no check at the end. Three rules, all non-negotiable:

  1. Never paraphrase a source doc into a subagent prompt. Tell it to read docs/notes/source-access.md itself. The failed prompts summarised the recipe; the prompts that worked said "read the file."
  2. Never offer "mark it unverified" as an escape hatch. Say: never invent a number; if you cannot fetch it, write not found and footnote what you tried. An honest gap beats a guess — a guess poisons every decision downstream.
  3. A task never marks its own fan-out done. A separate QA step must read the literal done_when text, grep the output for hedge words, and refetch a random sample of numbers to confirm they are real. Only then flip the status.

One subagent per round gets the browser — see the contention note in source-access.md. Parallel browser agents hijack each other silently.

Cost per round

The $2.00/round cap is gone — it was removed 2026-08-27 after it broke the first research round ($2.0049, error_max_budget_usd). That squeeze is what made subagents guess numbers instead of fetching them. Research rounds with fan-out need room. If a cap is ever restored, NIGHTSHIFT_MAX_USD (~$5) is the setting, and it is Matt's to change — never shrink the research to fit a cap; stop and say so instead.

Standing limits (from CLAUDE.md, unchanged)

Publish nothing, buy nothing, touch no accounts. Domain purchase is approved in principle but Matt buys it himself — the agent only shortlists and checks availability.

The site is the second channel — keep it current

Matt reads Telegram and HTML. Nothing else. The whole preview site is generated from docs/ + data/ by bin/build_site.py, and pushed by bin/publish.sh. Hub, canonical docs, decision log, research notes, session log and the queue are all pages on it. Run bin/publish.sh at the end of any round that changed a doc or a deliverable — a Telegram message with no updated page behind it is half a report. Never hand-edit data/site/; it is wiped on every build.
